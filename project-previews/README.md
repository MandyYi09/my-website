# Live project covers

Walker uses the original sketch from MandyYi09/walker. Glitch uses the local project sketch. The p5 runtime is shared with Circle Multiplication; the adapter limits thumbnail rendering to 30 fps and removes page margins.

Shapes uses a cover-only renderer in `grid-2/preview.js`; the original `grid-2/sketch.js` and external project remain unchanged. It preserves the 12px grid, gray background, white shapes, dark outlines and 33/33/34 random choice. Three shapes are rasterized once into a small sprite atlas, then copied each frame instead of rebuilding each cell's vector paths through p5. Animation runs in an OffscreenCanvas worker when supported, uses the gallery frame budget, and freezes offscreen. The shared renderer provides a main-thread compatibility fallback without loading p5.

Align Studio uses `align-studio/index.html`, a local cover of the existing reference figure, with reach/warrior/tree/side poses at the original 3.2-second interval. The reference data is copied unchanged from sibling `Align-Studio/src/reference.mjs` by `node scripts/sync-align-cover.mjs`. Shared geometry, instanced joints and bones, native card resolution and worker rendering reduce cover overhead. No camera, tracking model, application UI or CDN is loaded. Both Projects and the homepage wait for an actual rendered frame, then retain/freeze the same-origin preview. Full project links still open the canonical Align Studio application.

SportX uses `sportx/index.html`, an isolated canvas rendering the current SportX athlete and captured `rowing-full` (全桨划) clip, including its reviewed 0.5–8.05 second action window. It loops the capture at its original 1× speed while rotating the whole athlete/boat/oar scene 360° every 60 seconds. Framing is fitted over the full action and turn so it stays fixed. Rendering targets 30 fps, without loading the SportX page, controls, camera tracking or other movements. `assets/images/projects/SportX/rowing-full-cover.png` is a screenshot of that same renderer. Run `node scripts/sync-sportx-cover.mjs` from this repository after updating the sibling `SportX` source to refresh the vendored source modules and full-stroke capture. The copied sampler accepts an optional track list so the card fetches only full stroke; the remaining source modules are copied unchanged.

The SportX card starts at a 45° three-quarter turn. Its close framing fits the athlete and boat through the full cycle; distant blade tips can extend past the card edge. The still cover uses the same enlarged framing and starting angle.

SportX and the sculpture card use module workers with OffscreenCanvas through `worker-preview.js`. Model loading/parsing, athlete construction, framing calculations and steady animation run off the browsing thread. `warmup-scene.js` compiles materials and primes textures/geometry in batches before an asynchronous GPU fence confirms that the first complete frame is ready to reveal. Initialization uses timer yields because browsers can suspend animation callbacks for a transparent loading iframe. The lightweight iframe host forwards status, resize and visibility events, and terminates its worker on page exit. Browsers without OffscreenCanvas use the same renderer on the iframe thread; worker errors keep the static screenshot without a costly automatic main-thread retry. Local Three.js r180 helper modules in `vendor/` use the shared SportX vendor runtime so workers do not depend on document import maps or CDN imports.

Modern Shuilu uses `zhong-art/index.html`, a dedicated build sharing `carousel-artwork`, `carousel-motion` and styles with the sibling `zhong-art` website's `GuardianCarousel`. It preserves the three current characters, breathing motion and seven-second rotation without loading React, the router, collection, version polling or a nested remote website. Images use responsive 180/360px derivatives with original-resolution fallbacks; the preview renders at the card's native size. Its same-origin lifecycle freezes CSS animations and the carousel, retaining their instance offscreen. The homepage uses the same cover and waits for decoded artwork before revealing it. Decoded-image counts feed the gallery loading bar; they are not byte counts. Rebuild with `node scripts/sync-shuilu-cover.mjs` after changing the source carousel. The full project link still opens the canonical website.

Other website previews load the portfolio homepage pinned to Walker in a scaled desktop viewport. No camera is enabled by any cover.

The sculpture card loads `cloud-gate/sculpture-preview.glb.gz`, a baked thumbnail model, instead of generating geometry and procedural textures in the browser. Static meshes and cloud meshes are batched by material; cloud phases are retained as a vertex attribute and animated in the vertex shader. Its source artwork is unchanged at full detail. To regenerate after editing the sculpture, serve the website locally, open `scripts/bake-sculpture-preview.html?detail=card`, and save the generated download over the asset. Rebuild before changing the asset version in `cloud-gate/preview.js`. This loader expects a gzip file served as a binary file (without an additional `Content-Encoding: gzip` header).

The current card asset contains 294,606 triangles in 22 meshes (8.4 MB compressed), compared with 1,265,364 triangles in 119 meshes in the full procedural model. Thumbnail tessellation is opt-in through `detail=card` on the bake page; ordinary source views retain the full geometry.



Covers notify the gallery only after rendering; still images remain as fallbacks. Offscreen frames are frozen and retained, including their document, animation phase, video position and GPU resources. Returning resumes the same instance. Opening a dialog, hiding the tab or pausing animation also freezes existing cards instead of unloading them. Local previews install `preview-lifecycle.js` before application scripts to suspend animation callbacks, timers, video and CSS animations. Worker renderers stop their loops and pause unfinished GPU warmup while frozen. Remote documents that cannot run the local controller retain their iframe but rely on native browser rendering throttling.

The desktop cache retains up to 12 frames (covering all 11 live cards). Reported device memory of 4 GB limits this to 8 frames, and 2 GB or less to 4. If the browser exposes JS heap usage above 80% of its limit, the cache also reduces to at most 4. Eviction only unloads least-recently-used frozen/offscreen frames; visible frames are protected. Removing cards during filtering and explicit failures still discard their frames. These are conservative budgets, not a claim to measure exact GPU memory availability.

Each live card keeps a local project screenshot visible underneath the iframe until its first-frame readiness message arrives. Visible queued/loading covers show an indeterminate loading bar; the sculpture card reports actual streamed download progress followed by model/first-frame preparation. Pausing hides the bars, and an explicit preview failure leaves the screenshot in place. Pause then play retries failed covers. A frame's navigation/load event alone never replaces the screenshot.

Project collections appear independently as their requests finish. Live covers start one at a time after a short idle gap, deferred during scrolling and input. After four seconds a slow cover releases the queue while continuing to load; its still image stays until it announces readiness, even if that happens later. Idle callbacks have a one-second deadline so existing animations cannot starve new ones. Collection requests time out after 15 seconds, and a failed collection leaves the available projects usable with a retry button.

Once ready, every visible cover continues animating during scrolling, typing and clicks. The p5, painting, SportX and baked sculpture covers target 30 fps with one canvas pixel per CSS pixel. SportX also skips the hidden wrist panel's WebGL context in embedded mode, and keeps pose transitions time-based at the lower frame rate. Full project views retain their existing resolution and frame rates.
